# Phase 3 — CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A practical `/admin` area where an admin signs in and manages all site content and images through Supabase. The database's RLS stays the real gate.

**Architecture:** The admin routes are client-only (SPA fallback). A layout route guards them: its `clientLoader` checks the session and `rpc('is_admin')`. Data access lives in `src/services/admin/*`: one generic CRUD module plus a few specific ones. Pages use shared admin components. Image handling is a pure, tested pipeline (`utils/encodeImage.ts`, `utils/mediaPath.ts`) wrapped by `services/media.ts`.

**Tech Stack:** React 19, React Router 7, Supabase JS v2, Zod, Tailwind 4, Lucide, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-17-mondelos-website-design.md`. The sections used here are §8, §9.1, §9.4 and §11.

## Global Constraints

Everything in [README → Global Constraints](README.md#global-constraints-apply-to-every-task-in-every-phase) applies. In addition:
- **Admin look:** ivory background, a `forest-900` sidebar and DM Sans. Section titles in Playfair. No marketing styling. Below `lg`, the sidebar becomes a top bar with a menu, and list tables become stacked cards.
- **Copy:** plain words for a non-technical park owner. For example, "Publish on website" rather than "is_published".
- **Errors:** never show a raw Supabase error. Map errors through `toFriendlyError` (Task 2).
- **Empty strings become `null` before every write.** Since Phase 1 the database rejects `''` in URL, email, link and CTA columns, and its "both or neither" checks treat `''` as set. Services must convert blank optional fields to `null`.
- **Internal link pattern:** use `^(/([^/\\[:cntrl:]]|$)|https://)`, the same pattern the database will use. This rejects `/\evil` and control characters, which browsers turn into links to other sites.
- **Admin code:** route-level lazy loading only, so admin code never lands in the public bundle (checked in Phase 4 Task 5).

## Review Focus
1. **A session that expires while the admin is editing.** The save fails with a friendly "Your session has expired — please sign in again" message, and the form keeps its values (a draft in `sessionStorage`) after re-login. → Task 1 and Task 2 test it.
2. **Uploading a 20 MB photo, a HEIC file or a 300px image as a cover.** Each is rejected before any upload, with a specific message. → Task 3 tests it.
3. **Deleting a photo that is still in use.** The admin sees which items use it, not a database error. → Task 3 tests it.
4. **Two attractions given the same slug.** A friendly "That web address is already used by another attraction" message, mapped from `23505`. → Task 5 tests it.
5. **Leaving a form with unsaved changes** (sidebar link or browser back). A confirmation prompt appears. → Task 2 tests it.

### Task 3: Media pipeline, uploader, image picker, media library

**Files:**
- Create: `src/utils/slug.ts`, `src/utils/mediaPath.ts`, `src/utils/encodeImage.ts`, `src/services/media.ts`
- Create: `src/admin/components/MediaUploader.tsx`, `ImagePicker.tsx`, `FocalPointPicker.tsx`, `src/admin/pages/MediaLibraryPage.tsx`, `src/routes/admin/media.tsx`
- Test: `src/utils/slug.test.ts`, `src/utils/mediaPath.test.ts`, `src/utils/encodeImage.test.ts`, `src/services/media.test.ts`, `src/admin/pages/media-library.test.tsx`

**Interfaces:**
- Produces:
  - `slugify(input: string, maxLength = 60): string`. Lowercase ASCII (diacritics stripped via NFKD), non-alphanumerics → `-`, collapsed and trimmed. Returns `'image'` when the result is empty.
  - `shortId(): string`. 6 characters, `[a-z0-9]`, from `crypto.getRandomValues`.
  - `buildMediaPath({ year: number; base: string; id: string; width: number; ext: 'webp' | 'jpg' }): string` → `"2026/blue-lagoon-ab12cd-960.webp"`.
  - `VARIANT_WIDTHS = [480, 960, 1600, 2400] as const`.
  - `planVariantWidths(originalWidth: number): number[]`. Keeps the widths ≤ the original. If the original is narrower than 480, returns `[originalWidth]`.
  - `validateImageFile(file: File, purpose: 'cover' | 'gallery', dims?: { width: number; height: number }): { ok: true } | { ok: false; message: string }`:
    - type must be in `['image/jpeg','image/png','image/webp']`, else "Please choose a JPG, PNG or WebP photo." (HEIC included);
    - size ≤ 15 MB, else "That photo is larger than 15 MB. Please use a smaller version.";
    - when `dims` is given, the long edge must be ≥ 800 for `cover`, else "This photo is too small for a large image (at least 800 px wide is needed)." For `gallery`, a small image returns ok (the UI warns separately).
  - `encodeVariant(bitmap: ImageBitmap, width: number): Promise<{ blob: Blob; ext: 'webp' | 'jpg' }>`. Draws to a canvas scaled to `width`, then `toBlob('image/webp', 0.8)`. If the returned `blob.type !== 'image/webp'` (Safari), it re-encodes with `toBlob('image/jpeg', 0.82)`.
- Produces in `services/media.ts`:
  - `uploadImage(file: File, altText: string, purpose: 'cover' | 'gallery'): Promise<MediaRow>`. Steps: validate → `createImageBitmap` → validate dims → encode every planned width → upload each to bucket `media` (`contentType` set, `cacheControl: '31536000'`, `upsert: false`) → insert the `media` row (`storage_base_path` = the path without the `-{width}.{ext}` suffix, `variants`, `width`, `height`, `alt_text`, `original_filename`). Any failure removes the already-uploaded objects, then throws an `AdminError`.
  - `updateMedia(id, { altText?, focalX?, focalY? })`
  - `deleteMedia(row: MediaRow): Promise<void>`. Deletes the DB row first. On `23503`, it throws `MediaInUseError` with `usedBy: string[]`, found by querying `page_sections`, `attractions` (cover), `attraction_images`, `gallery_images` and `site_settings` for that media id. After the row is deleted, it removes every variant object.
  - `findMediaUsage(id): Promise<string[]>`. Labels look like `"Attraction: Scenic Views"` or `"Gallery image"`.
- Produces components:
  - `<MediaUploader purpose multiple? onUploaded(rows: MediaRow[]) />`. Has a file input and a drop zone, and requires alt text per file before uploading (a list with one alt input each, pre-filled from the filename words). Shows per-file progress and errors. Warns "Small photo — it may look blurry" for gallery images under 800px.
  - `<ImagePicker value: MediaRow | null onChange purpose />`. Shows the current thumbnail, "Choose from library" (opens a modal grid) and "Upload new".
  - `<FocalPointPicker media onChange />`. Click on the image sets `focalX` and `focalY` (0–100). It is also keyboard-operable with arrow keys in steps of 5.
- **Media library page** (`/admin/media`): a grid with each image's alt text. Clicking an image opens an editor (alt text, focal point, the "Used by" list, Delete). Deleting an in-use image shows "This photo is used by: …" and does not delete.

  - `buildMediaPath({year:2026, base:'blue-lagoon', id:'ab12cd', width:960, ext:'webp'})` → `'2026/blue-lagoon-ab12cd-960.webp'`.

    - Counts use `select('id', { count: 'exact', head: true })`.
    - `recent` comes from the `recent_content_updates` view.
    - `missing` is `computeMissing(settings, sampleCount, testimonialCount, galleryCount)`.
  - `computeMissing(...)` returns human items in this order:
    1. "Phone number" if no phone;
    2. "Email address";
    3. "Opening hours";
    4. "Social media links" if all four are null;
    5. "Google Maps listing link";
    6. "Guest reviews" when there are 0 testimonials;
    7. "Park photos" when there are 0 gallery images;
    8. "{n} sample items still to confirm" when the sample count > 0.

- **Dashboard:** 4 count tiles, a "Recent updates" list (linking to each item's editor), and a "Still missing" checklist linking to the relevant admin page.
